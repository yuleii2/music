# 吉他和弦学习软件前端重构执行规格

> 文档用途：本文件是新版 Android 前端的产品、交互、视觉、技术与验收统一规格。后续 Codex 应能够在不重新猜测产品意图的前提下，按照本文件分阶段完成重构。
>
> 文档状态：可执行方案
>
> 当前产品版本：Android V1.3
>
> 目标平台：Android，保留 minSdk 23 与 targetSdk 36；手机为第一优先级，同时支持横屏、平板与折叠屏的自适应布局。

---

## 1. 执行摘要

### 1.1 最终目标

彻底替换当前由 Java + Android View 动态创建的前端，构建一套适合吉他和弦学习、练习和编排的现代 Android 界面。

新版前端暂定设计概念为“Studio Flow｜流动琴房”。这是内部设计概念，不代表必须修改应用正式名称。除非另有明确需求，应用对外名称仍沿用现有名称。

新版必须同时满足以下目标：

1. 完整保留现有离线业务能力和 AI 安全边界。
2. 重新组织信息架构，让用户在两次点击内到达主要功能。
3. 大幅增加有意义的状态动画、共享元素动画、指板动画和播放反馈。
4. 从渲染架构上解决当前全量创建 View、整页重建和搜索时整块重绘的问题。
5. 支持浅色、深色、字体放大、TalkBack、减少动画和预测返回。
6. 在中端 Android 设备上实现稳定的 60 Hz；在高刷新率设备上正确适配 90/120 Hz。
7. 最终删除旧前端，但不得在新版功能对齐前提前删除旧页面或破坏现有业务逻辑。

### 1.2 已确定的技术方向

- 新前端语言：Kotlin。
- UI 框架：Jetpack Compose + Material 3。
- 自适应布局：Material 3 Adaptive 或当前稳定的官方等价方案。
- 页面状态：ViewModel + StateFlow + SavedStateHandle。
- 导航：当前稳定版 Navigation Compose，使用单 Activity 架构。
- 依赖注入：第一阶段使用轻量 AppContainer 和显式 ViewModel Factory，不为了重构而强制引入 Hilt。
- 现有 Java 乐理、音频、存储、导出和 AI 核心继续复用。
- 指板最终使用 Compose Canvas 重写；允许迁移早期短暂使用 AndroidView 包装旧 FretboardView，但最终交付中不得依赖旧 View 前端。
- Gradle 暂时保留现有 Groovy DSL，不把构建脚本迁移为 Kotlin DSL，避免扩大无关改动。
- 所有新增 AndroidX 与 Compose 依赖使用执行时的最新稳定兼容版本，不使用 alpha、beta 或未稳定 API，除非官方稳定能力无法满足且文档中明确记录原因。

### 1.3 明确不做的内容

本次重构不应顺带实现以下内容：

- 用户账号、登录或云同步。
- 录音、音频导入、MIDI 编曲或完整 DAW 能力。
- iOS、Web、HarmonyOS 或桌面客户端。
- 七弦吉他、贝斯、尤克里里或任意自定义调弦。
- 未经验证的自动指法生成。
- 改写已通过测试的乐理核心算法。
- 更换本地数据格式，除非为新版 UI 状态持久化增加独立、向后兼容的轻量数据。
- 在 UI 重构期间修改 AI 的安全边界、密钥存储或本地校验规则。

## 2. 当前系统基线

### 2.1 当前技术与数据

现有项目位于 D:/K2/music，主要结构如下：

- app/src/main/java/com/k2/music：Java 业务逻辑与旧 View 前端。
- app/src/main/assets/chords：和弦公式和吉他指法 JSON。
- app/src/test：离线核心测试。
- docs/requirements.md：产品需求。
- docs/implementation-report.md：现有四阶段实现与验收记录。

当前核心数据与能力：

- 26 种和弦公式。
- 202 条内置吉他指法。
- 十二个根音的理论和弦生成。
- 名称规范化、别名、Unicode 升降号和 slash chord。
- 多指法详情、收藏、历史、试听和图片/SVG 导出。
- 反向识别、自定义指法、移调和变调夹。
- 和弦进行、播放器、节拍器、练习、推荐和统计。
- 默认关闭的 OpenAI Compatible AI 增强层。

### 2.2 必须复用的核心类

实现新版 UI 时应优先复用下列现有能力，不应在 Compose 层复制算法：

- ChordRepository、ChordDataLoader、ChordNameParser、ChordTheoryEngine。
- GuitarVoicingRepository、ChordFormulaRepository。
- ChordIdentifier、ChordMatchScorer、EditableFretboardView 背后的识别算法。
- ChordTransposer、CapoAssistant。
- ProgressionStore、ProgressionPlayer、ProgressionPresetRepository。
- MetronomeEngine、AbsoluteTimeScheduler。
- PracticeRecordStore、PracticePreferencesStore、PracticePlanDraftStore。
- VoicingRecommendationEngine、VoicingTransitionScorer。
- ChordAudioPlayer。
- UserChordStore、CustomVoicingStore。
- VoicingImageExporter、VoicingSvgExporter、SvgVoicingRenderer。
- AiService、AiSettingsStore、AiResultValidator、AiResultCache。

允许为这些类增加只读适配器、接口包装和线程边界，但不得无理由改写其内部算法。

### 2.4 当前前端已知问题

后续实现必须针对这些根因，而不是只更换颜色：

1. MainActivity 在切换页面时 removeAllViews 并重新创建页面和底部导航。
2. UiFactory.scrollPage 使用普通 ScrollView 包裹完整 LinearLayout。
3. HomePage 的和弦库在每次搜索文本变化时 removeAllViews 并创建完整网格。
4. 和弦库没有 RecyclerView 或 Lazy 布局，所有卡片一次性参与测量与布局。
5. 当前动画主要是统一的页面淡入、轻微位移和指板缩放，无法表达页面间空间关系。
6. 底部“添加”实际承担工具中心职责，导航语义不准确。
7. 首页顶部“推荐/和弦库”与底部“和弦库”入口重复。
8. 收藏是低复杂度功能，却占据一个底部主导航。
9. 导出被放在“我的”，详情页需要跨页面跳转。
10. 进行、练习、AI 设置等复杂页面以长表单连续堆叠，核心任务和高级配置没有分层。
11. Unicode 字符被用于底栏和操作图标，不同字体和设备可能呈现不一致。
12. 现有配色只有白、黑、灰、蓝，没有完整深色模式和产品化视觉语义。

## 4. 体验原则

### 4.1 两次点击原则

从任意一级主页面开始，用户应在两次点击内到达：

- 和弦搜索。
- 反向识别。
- 移调/变调夹。
- 和弦进行。
- 开始练习。
- 收藏和弦。

### 4.2 渐进披露

默认展示完成任务所需的最少信息，高级配置通过底部抽屉、折叠区或“更多设置”进入。

示例：

- 练习首页只显示模式、和弦和时长；熟练度、横按限制、最高品位放在练习偏好。
- 和弦详情首屏显示名称、指板、按法、试听；理论说明放在下方折叠区。
- 和弦进行默认显示和弦时间轴与播放控制；推荐策略、扫弦和逐步配置在步骤编辑器中。

### 4.3 动画服务于理解

动画必须至少完成一项作用：

- 说明元素从哪里来到哪里去。
- 说明选择或状态发生了什么变化。
- 说明播放、节拍或练习进度。
- 提供操作成功、吸附或完成反馈。

禁止为了“看起来高级”而加入长期循环的粒子、模糊、旋转、视差或无意义弹跳。

### 4.4 离线优先

所有离线能力必须在 AI 未配置、网络断开或请求失败时正常工作。AI 入口不得压过本地核心功能。

### 4.5 单手与可达性

高频主操作应位于屏幕中下部或底部固定区域。返回、设置、分享等低频操作可位于顶部。

## 5. 新版信息架构

### 5.1 一级导航

手机使用五项底部导航：

1. 首页
2. 和弦
3. 工具
4. 练习
5. 我的

不再设置底部“收藏”和“添加”。

平板或横向大窗口使用 Navigation Rail；展开窗口允许列表与详情双栏。

### 5.2 全局导航规则

- 一级页面显示主导航。
- 和弦详情、识别、移调、进行编辑、AI 助手等二级任务页面隐藏底部主导航，使用顶部返回和自己的底部操作区。
- 沉浸练习隐藏顶部与底部导航，只保留练习 HUD。
- 正在播放和弦、进行或节拍器时，在一级页面底栏上方显示 MiniPlayer。
- 进入二级页面后，如果页面有自己的播放控制，不重复显示 MiniPlayer。
- 返回手势必须支持预测返回；取消返回手势后页面状态不得丢失。
- 相同和弦详情不得重复压入导航栈。
- slash chord 不能直接作为未编码路径段。详情路由使用编码后的查询参数或类型安全参数。

### 5.3 推荐路由

路由命名可以根据实际导航库调整，但语义必须保持：

## 6. 页面详细规格

### 6.1 启动与加载

#### 页面目标

用户应尽快看到可理解的启动状态，并在数据加载完成后进入首页。

#### 内容

- 使用官方 SplashScreen API 或当前稳定等价方案。
- 启动画面只展示图标和单色背景，不使用长动画。
- Repository 加载期间首页展示骨架结构，不显示空白屏。
- 使用安全回退数据时，在首页顶部展示可关闭的提示条。
- 数据加载失败且回退也不可用时展示全屏错误页，包含重试和问题说明。

#### 验收

- 启动过程不能阻塞主线程解析大型 JSON。
- 旋转设备或进程重建时不能重复创建多个加载任务。
- 错误提示不能泄露文件路径、API Key 或内部堆栈。

### 6.2 首页

#### 页面目标

让用户立即搜索、继续练习或回到最近任务，不把首页变成静态宣传页。

#### 从上到下布局

1. 顶部栏：应用名称/问候语、搜索图标或头像入口。
2. 大型全局搜索框：提示“输入 Cmaj7、Am、G/B……”。
3. 继续区域：
   - 有未完成练习时显示“继续练习”。
   - 有最近进行时显示“继续编辑/播放”。
   - 两者都没有时显示“开始第一次练习”。
4. 最近查看和弦横向列表，最多展示 8 个。
5. 今日建议或入门推荐，最多展示 4–6 个，避免一次渲染全部和弦。
6. 工具快捷入口：识别、移调、进行；最多三项。

#### 交互

- 点击搜索框进入全屏搜索状态，键盘自动弹出。
- 输入时展示最近记录、匹配结果和示例。
- IME 搜索遇到合法和弦时直接进入详情。
- 非法输入显示就地说明，不使用只有 Toast 的错误反馈。
- 最近查看支持长按移除；移除后提供撤销。

#### 状态

- Loading、Content、EmptyHistory、FallbackData、Error。
- 页面应记住滚动位置和搜索前状态。

#### 动画

- 搜索框展开为全屏搜索使用共享边界动画。
- 最近和弦首次出现可错峰淡入，最多 6 项，每项间隔不超过 24ms。
- 首页恢复时不重复播放整页入场动画。

### 6.3 和弦库

#### 页面目标

高效浏览、搜索、收藏、管理和批量处理和弦。

#### 顶部结构

- 吸附搜索框。
- 分段控件：全部、收藏、最近、自定义。
- 筛选按钮与当前结果数量。
- 激活筛选时，在搜索框下方显示可关闭的筛选标签。

#### 列表

- 手机使用 LazyVerticalGrid。
- 紧凑宽度默认两列；字体放大或极窄设备允许一列。
- 展开窗口允许三至四列，或左侧列表右侧详情。
- 卡片稳定 key 使用规范化和弦 symbol。
- 卡片 contentType 按“有指板预览/无指板预览/自定义”分类。

#### 和弦卡内容

- 标准和弦名。
- 中文类型或简短英文类型。
- 组成音。
- 难度标签。
- 横按/开放/简化标签之一。
- 迷你指板。
- 收藏状态。

#### 搜索与筛选

- 搜索 Flow 使用 120–160ms debounce、distinctUntilChanged 和 mapLatest。
- 过滤计算放在 Dispatchers.Default。
- 输入合法完整和弦并点击搜索时进入详情。
- 普通关键词搜索类型、音名和别名。
- 筛选项：根音、类型、难度、开放/横按/简化。
- 默认折叠筛选，在 ModalBottomSheet 中展示。

#### 多选

- 长按卡片进入多选模式。
- 多选操作：收藏/取消收藏、批量导出、加入练习。
- 系统返回先退出多选，不直接离开页面。

#### 空状态

- 收藏为空：提供“浏览和弦”按钮。
- 自定义为空：提供“识别并保存指法”入口。
- 搜索无结果：保留搜索词并提供清除筛选。

#### 性能要求

- 禁止使用 Column/ScrollView 一次创建全部卡片。
- 搜索和筛选时只更新变化项目，不重建整个 Scaffold。
- 快速输入时旧筛选任务必须取消。

### 6.4 和弦详情

#### 页面目标

在首屏完成“看按法、切按法、试听、收藏”的闭环。

#### 布局

1. 顶部栏：返回、标题“和弦详情”、更多菜单。
2. Hero：
   - 大号和弦名。
   - 中文类型和英文类型。
   - 收藏状态。
3. 信息摘要：根音、组成音、音程结构。
4. 大型指板。
5. 按法选择器：横向卡片或分页指示器。
6. 固定底部操作栏：试听按法、收藏；更多动作进入菜单。
7. 下方信息区：学习提示、和弦说明、实际发声音、按法参数。

#### 按法类型

- 内置按法。
- 简化按法。
- 横按按法。
- 自定义按法。
- 无已收录按法的理论和弦。

无按法时仍显示理论信息，并将主按钮改为“试听组成音”。

#### 操作

- 左右滑动切换按法。
- 点击按法标签直接跳转。
- 试听当前按法。
- 收藏/取消收藏。
- 标记/取消熟悉按法。
- 导出当前按法或当前和弦全部按法。
- 打开 AI 解释，并自动带入当前和弦，不再要求用户重复输入。
- 自定义按法允许编辑和删除；内置按法不得删除。

#### 指板动画

- 静态琴弦、品丝和弦枕不随按法切换重新淡入。
- 每根弦的标记以弦索引为 key。
- 同一弦从旧品位到新品位时，圆点沿弦平滑移动。
- O、X 和按弦点之间使用交叉淡化。
- 横按使用圆角矩形宽度和位置插值。
- 不匹配的旧标记先淡出，新标记再淡入，避免瞬移。
- 指法数字跟随圆点，不单独滞后。

#### 共享元素

- 从和弦卡进入详情时共享和弦名、卡片容器和迷你指板。
- 返回时反向还原。
- 如果来源卡片已滚出屏幕，则安全退化为标准淡入/滑入，不得闪退。

### 6.5 工具首页

#### 页面目标

取代当前“添加”页面，集中展示离线音乐工具。

#### 内容

- 最近使用的工具。
- 反向识别。
- 移调与变调夹。
- 和弦进行。
- 独立节拍器快捷启动。
- AI 助手，仅在已启用或用户主动查看时强调。
- 每个卡片显示一句用途说明和最近状态。

工具页不放和弦名称输入框；和弦搜索由首页和和弦库承担。

### 6.6 反向识别

#### 模式

- 交互指板。
- 音符输入。

使用顶部 SegmentedControl 切换，保留两种模式各自输入状态。

#### 交互指板

- 支持设置品位、空弦、闷弦、擦除和清空。
- 上一把位/下一把位使用明确图标和数值。
- 点击琴弦后标记通过弹簧动画出现。
- 擦除和清空提供视觉反馈；清空后提供撤销。

#### 候选结果

- 用户输入达到可识别条件后实时计算，必要时使用短防抖。
- 展示最多五个候选和评分解释。
- 完全匹配、转位、缺根音、额外音使用文字标签，不只依赖颜色。
- 每个候选支持详情、试听、收藏。
- 指板输入可以保存为自定义指法。

#### 保存自定义指法

使用底部抽屉收集：

- 所属和弦。
- 指法名称。
- 手指编号，可选。
- 起始品位。
- 备注。

保存前必须继续使用本地引擎校验。

### 6.7 移调与变调夹

#### 页面结构

顶部使用“移调”和“变调夹”两个分段页面，不再把两套长表单纵向堆叠。

#### 移调

- 支持单个和弦和空格分隔的进行。
- 半音范围 -11 至 +11。
- 使用滑块配合减号/加号按钮。
- 支持升号/降号偏好。
- 结果实时更新。
- slash bass 同步移调。
- 支持复制全部、打开第一个和弦、加入和弦进行。

#### 变调夹

- 模式 A：目标实际和弦 + 希望使用的指法，寻找 0–12 品。
- 模式 B：已知指法 + capo 品位，计算实际声音。
- 品位使用可点击刻度和数值。
- 推荐结果显示“形状、变调夹、实际声音”三列关系。

### 6.8 和弦进行

#### 页面分层

分为三个层级：

1. 进行列表：本地进行、预设、新建。
2. 进行编辑器：时间轴、和弦步骤、基本设置。
3. 步骤编辑抽屉：按法、拍数、扫弦、顺序等高级属性。

#### 进行列表

- 显示名称、调性、BPM、拍号、步骤数和最近修改时间。
- 支持加载、复制、重命名、删除。
- 删除使用确认对话框，并在删除后提供撤销。
- 预设与用户进行视觉区分。

#### 编辑器

- 顶部显示名称和保存状态。
- 中部使用横向时间轴展示和弦块。
- 和弦块支持拖动排序。
- 点击和弦块打开步骤编辑抽屉。
- 添加入口支持一次输入多个和弦。
- 当前步骤显示大型指板，下一步骤显示小型预览。
- 推荐按法显示推荐理由。

#### 播放

- 底部固定控制：上一项、播放/暂停、下一项、停止。
- 显示 BPM、拍号、循环和播放模式。
- 支持整和弦/分解和弦。
- 当前时间轴卡片随播放高亮并自动滚入可见区域。
- UI 只观察 ProgressionPlayer 状态，不能用 Compose delay 驱动音频。

#### 草稿

- 编辑变化后 500–800ms 自动保存 UI 草稿。
- 正式“保存”仍写入 ProgressionStore。
- 异常退出后可以恢复未保存草稿。
- 草稿必须有版本号，不能覆盖已保存进行。

### 6.9 练习首页

#### 页面目标

把练习设置、正在练习和历史统计分开，避免全部堆在一个表单中。

#### 内容

- 快速开始卡：上次练习配置。
- 模式：双和弦、多和弦、随机挑战。
- 今日练习分钟数。
- 最近七天统计。
- 最常练习和弦。
- 练习偏好入口。

点击开始后先进入轻量设置页，再进入沉浸练习。

### 6.10 练习设置

- 选择练习模式。
- 输入或选择和弦。
- 时长快捷项：30 秒、60 秒、自定义。
- BPM。
- 拍号。
- 每拍/每小节切换。
- 首拍重音。
- 高级设置折叠：横按许可、最高品位、推荐模式。

所有输入实时校验。主要按钮只有“开始练习”。

### 6.11 沉浸练习

#### 布局

- 顶部：剩余时间、暂停。
- 中央：当前和弦名和大型指板。
- 辅助：下一和弦预览。
- 节拍环或拍点指示。
- 底部：完成一次、当前完成数、连续次数。

#### 动画与音频

- 首拍使用更强的视觉脉冲，其他拍使用轻脉冲。
- 脉冲时间来自 MetronomeEngine/AbsoluteTimeScheduler 的时间锚点。
- 切换和弦时名称与指板共享状态过渡。
- 下一和弦从右侧进入，当前和弦向左淡出。
- 暂停后立即停止视觉节拍，不继续空转。

#### 生命周期

- 应用进入后台必须暂停或安全停止。
- 返回时弹出“结束练习/继续练习”确认。
- 旋转或窗口变化不能重置计时和次数。

### 6.12 练习结果

- 实际时长。
- 完成次数。
- 最佳连续次数。
- 练习过的和弦。
- 与最近一次结果的简单对比。
- 再练一次、调整设置、完成。

结果保存失败时明确提示，但不能丢失当前可见总结。

### 6.13 AI 助手

#### 原则

- AI 是可选增强层，默认关闭。
- 所有 AI 结果必须继续经过本地验证。
- 未配置时展示说明和设置入口，不假装正在联网。
- API Key 永不回显。

#### 页面

- 顶部任务模板：推荐和弦、推荐进行、解释和弦、优化进行、练习计划、切换建议、情绪生成。
- 输入区根据任务变化。
- 发送后展示明确的加载、取消、错误状态。
- 结果卡包含“AI 建议”和“本地验证”两个清晰区域。
- 本地验证失败的候选不得提供保存为正式数据的主操作。
- 用户确认后才允许保存进行或练习草稿。

#### 从上下文进入

- 从详情进入“解释和弦”时自动带入 symbol。
- 从进行进入“优化进行”时自动带入当前步骤。
- 从练习进入“练习计划”时自动带入本地摘要，但发送前让用户确认。

### 6.14 我的与设置

#### 我的

- 练习概览。
- 学习偏好。
- 外观与动画。
- AI 状态。
- 数据与导出。
- 关于软件。

“最近查询”不再重复放在我的页。

#### 外观与动画

- 主题：跟随系统、浅色、深色。
- 动画：完整、简化、关闭。
- 新手模式/专业模式。
- 可选动态颜色，默认关闭以保持品牌视觉。

#### AI 设置

保留现有字段和安全规则：

- 启用状态。
- 服务名称。
- HTTPS Base URL。
- API Key 输入。
- 模型。
- 温度。
- 超时。
- 保存、测试连接、清除配置、清除缓存。

测试连接必须可取消，并显示结构化错误。

### 6.15 导出

#### 入口

- 详情页：导出当前按法/当前和弦全部按法。
- 和弦库多选：导出选择项。
- 我的 > 数据与导出：导出收藏或管理默认设置。

#### 设置

- 路径。
- 文件名前缀。
- JPG、PNG、SVG。
- 当前按法/全部按法。
- 背景和 SVG 可选项，如现有核心支持。

#### 进度

- 使用可取消的进度界面。
- 显示总数、已完成、成功、失败和首个文件名。
- 页面离开后任务状态不得丢失；如产品选择取消，则必须明确取消。
- 不在主线程执行图片或文件写入。

## 8. 动效与触觉系统

### 8.1 动效时长令牌

| Token | 时长 | 用途 |
| --- | --- | --- |
| instant | 90ms | 按压、颜色响应 |
| quick | 160ms | 图标、标签、局部淡入 |
| standard | 240ms | 抽屉、筛选、内容切换 |
| emphasized | 360ms | 卡片到详情、指板切换 |
| complex | 480ms 上限 | 多阶段练习结果，不得常用 |

### 8.2 缓动

- 标准进入：快速开始、平滑结束。
- 标准退出：快速离开，不拖延。
- 物理拖拽：跟手 1:1，释放使用中等阻尼弹簧。
- 指板手指移动：中等阻尼、低回弹，不做夸张果冻效果。
- 按钮按压：scale 最低不小于 0.97，避免明显缩小。

### 8.3 动效矩阵

| 场景 | 动效 | 时长/规则 |
| --- | --- | --- |
| 底部导航 | 图标形变、标签淡入、选中容器滑动 | 160–200ms |
| 搜索展开 | 搜索框共享边界扩展 | 240–320ms |
| 卡片进详情 | 容器、和弦名、指板共享元素 | 320–380ms |
| 按法切换 | 指板圆点移动、横按伸缩 | 260–360ms |
| 筛选结果 | animateItem 重排 | 160–240ms |
| 列表首次出现 | 最多 6 项错峰淡入 | 间隔 ≤24ms |
| 收藏 | 心形状态变换 + 轻弹簧 | 200–260ms |
| BottomSheet | 位移 + 遮罩透明度 | 240–320ms |
| 拖动进行 | 跟手移动 + 相邻卡片让位 | 实时 + 弹簧归位 |
| 播放和弦 | 发声弦或音符短暂高亮 | 与音频事件同步 |
| 节拍器 | 首拍强脉冲、普通拍轻脉冲 | 时间锚点驱动 |
| 练习切换 | 当前向左、下一项进入 | 240–320ms |
| 成功完成 | 进度环闭合、结果卡进入 | ≤480ms |
| 预测返回 | 页面随手势缩放/位移并预览目标 | 系统进度驱动 |

### 8.4 性能限制

- 同时持续动画的独立元素原则上不超过 8 个。
- 大列表不得给所有离屏项目播放入场动画。
- 高频动画优先修改 alpha、translation、scale 或 Canvas draw 参数。
- 避免每帧触发全文本重排和复杂测量。
- 禁止在滚动列表中使用大面积实时 blur。
- 禁止动画期间反复创建 Bitmap、Paint 或大型 Path。
- 指板静态几何使用 drawWithCache 或等价缓存。

### 8.5 减少动画

动画等级：

- 完整：全部设计动效。
- 简化：取消错峰、弹簧和大范围共享元素，保留短淡入和必要状态变化。
- 关闭：状态立即切换，保留系统所需最小反馈。

应用默认跟随系统 Animator Duration Scale/无障碍偏好，并允许用户进一步降低动画。

### 8.6 触觉

只在以下场景使用：

- 收藏成功/取消。
- 拖动步骤吸附。
- 变调夹或 BPM 刻度吸附。
- 清空、删除等明确操作确认。
- 练习完成。

不为页面导航、普通滚动和每个节拍默认振动。节拍振动如以后提供，必须由用户主动开启。

## 9. 技术架构

### 9.1 迁移策略

采用并行替换，而不是先删除旧 UI：

1. 新建 ComposeMainActivity.kt，保持旧 MainActivity.java 可编译。
2. 开发阶段将 Launcher 指向 ComposeMainActivity。
3. 通过适配层调用现有 Java 核心。
4. 每完成一个功能域就执行功能对齐测试。
5. P0 全部通过后删除旧 Page 类、UiFactory 和旧导航协调代码。
6. 最终可将 ComposeMainActivity 重命名为 MainActivity，但不是必需条件。

不得在 Phase 1 直接删除旧页面。

### 9.3 适配层

建议建立下列轻量接口：

- ChordCatalogGateway：查找、搜索、筛选、示例、全部和弦。
- UserLibraryGateway：收藏、历史、自定义指法。
- PlaybackController：单和弦试听、进行播放、停止和状态观察。
- RecognitionGateway：反向识别。
- TransposeGateway：移调和变调夹。
- ProgressionGateway：进行 CRUD、预设、推荐和草稿。
- PracticeGateway：偏好、记录、汇总和练习状态。
- ExportGateway：图片/SVG 导出。
- AiGateway：设置、请求、取消、缓存和结果验证。

这些 Gateway 只负责：

- 把 Java 回调包装为协程或 Flow。
- 明确后台线程和主线程边界。
- 将可变业务对象映射为稳定 UI model。
- 统一错误类型。

不得把乐理算法复制进 Gateway。

### 9.4 AppContainer

MusicApplication 中创建或持有 AppContainer：

- Repository 只初始化一次。
- UserChordStore、CustomVoicingStore 等共享实例按生命周期管理。
- Audio/Progression/Metronome 控制器必须有明确释放点。
- ViewModel 通过 Factory 获取依赖。
- 不允许 Composable 内直接 new 大型 Store、Repository 或音频引擎。

### 9.5 UI 状态

每个功能域使用不可变 UiState：

~~~text
HomeUiState
LibraryUiState
ChordDetailUiState
WorkbenchUiState
RecognitionUiState
TransposeUiState
ProgressionListUiState
ProgressionEditorUiState
PracticeHomeUiState
PracticeSessionUiState
AiAssistantUiState
ProfileUiState
ExportUiState
~~~

状态规则：

- 可持久显示的内容放 UiState。
- 导航、Snackbar、系统分享、打开文件夹选择器等一次性操作使用 UiEffect。
- 不使用 Boolean 事件反复触发导航。
- 搜索词、筛选、当前 segment、选中按法等可恢复状态写入 SavedStateHandle。
- Activity 重建后恢复当前路由与必要页面状态。
- 快速进度值只在最小 Composable 范围内收集，避免整页每帧重组。

### 9.6 导航状态

- 一级 Tab 各自保留返回栈与滚动位置。
- 再次点击当前 Tab：如果在子页面则回到根页面；已经在根页面则滚动到顶部。
- 深层页面使用 navigateUp，而不是跳转到固定首页。
- 详情页来源可以是首页、库、收藏、识别、AI 或进行，返回必须回到真实来源。
- 导航参数只传 ID/symbol，不传大型 Chord 对象。

### 9.7 指板 Canvas

FretboardCanvas 分为三层：

1. 静态层：弦、品丝、弦枕、品位编号。
2. 标记层：O、X、按弦点、横按、手指编号。
3. 播放层：当前发声音或弦的短暂高亮。

要求：

- 几何计算使用可测试的纯 Kotlin 数据结构。
- 静态层缓存。
- 所有品位和弦位置由尺寸计算，不写死像素。
- 支持紧凑卡片、详情、练习三种密度。
- 支持浅色/深色。
- 提供完整 semantics 描述，至少包含六弦到一弦品位、起始品位和指法名称。
- Canvas 不是唯一信息来源；无障碍用户仍能通过文本读取按法。

### 9.8 播放与节拍

- ChordAudioPlayer、ProgressionPlayer、MetronomeEngine 保持时间来源。
- Compose 只发送意图和观察状态。
- 视觉节拍按绝对时间锚点计算相位，不通过累积 delay 模拟。
- 页面离开、应用后台、Activity 销毁必须调用现有生命周期逻辑。
- MiniPlayer 与详情/进行/练习页面共享同一个播放状态源。
- 同时只允许一个主播放会话；启动新的播放前按现有规则停止或切换旧会话。

### 9.9 自适应布局

紧凑窗口：

- 底部导航。
- 单页详情。
- 详情和工具二级页面隐藏主导航。

中等窗口：

- 可使用 Navigation Rail。
- 和弦库两到三列。

展开窗口：

- Navigation Rail。
- 和弦库使用 ListDetailPaneScaffold 或等价双栏。
- 左侧选择和弦，右侧显示详情。
- 进行编辑器可使用左侧时间轴/列表、右侧指板与设置。

不得只依据物理设备类型判断；使用窗口尺寸类和当前可用空间。

## 10. 性能预算与实现规则

### 10.1 帧预算

- 60 Hz：每帧目标小于 16ms。
- 90 Hz：每帧目标小于 11ms。
- 120 Hz：每帧目标小于 8ms。
- 核心场景卡顿帧比例目标低于 1%。
- 任何主线程任务超过 50ms 都应调查。

### 10.2 响应预算

- 点击后 50ms 内出现按压或状态反馈。
- 普通页面转场在 400ms 内完成。
- 搜索防抖结束后 100ms 内提交首批结果。
- 筛选结果不阻塞输入。
- MiniPlayer 的播放/暂停状态在音频状态改变后下一帧更新。

### 10.3 列表

- 必须使用 LazyColumn、LazyRow、LazyVerticalGrid 或自适应等价组件。
- 所有业务列表提供稳定 key。
- 多类型列表提供 contentType。
- 不在 item Composable 中读取文件、解析 JSON 或创建 Store。
- 迷你指板不得每次重组重新解析 Voicing。
- 对滚动位置使用 rememberLazyListState，并按页面保存。

### 10.4 重组

- UiState 数据类保持真正不可变。
- 只有确认符合 Compose 稳定性要求时才使用 Immutable/Stable 注解。
- 高频 player progress 与大型页面状态分离。
- 使用 derivedStateOf 处理滚动派生状态。
- 不在 composition 中执行排序、过滤或大型字符串构建。
- 大型映射在 ViewModel/Default dispatcher 中完成。

### 10.5 绘制

- 使用 drawWithCache 缓存指板静态几何。
- 避免每帧修改大型 Path。
- 优先 drawLine、drawCircle、drawRoundRect。
- 不在动画期间创建 Bitmap。
- 导出继续走后台导出器，不复用屏幕截图作为正式导出。

### 10.6 启动

- 保留后台加载 Repository 的原则。
- 使用 Baseline Profile 覆盖：冷启动、打开和弦库、打开详情、切换按法、开始练习。
- Release 或 profileable 构建上测量，不以 Debug 流畅度作为最终结论。

### 10.7 推荐测量工具

- Macrobenchmark。
- Baseline Profiles。
- JankStats 或 FrameMetrics。
- Android Studio System Trace。
- Compose Layout Inspector 与 Recomposition Counts。
- adb shell dumpsys gfxinfo 作为辅助。

官方参考：

- https://developer.android.com/develop/ui/compose/performance
- https://developer.android.com/develop/ui/compose/lists
- https://developer.android.com/topic/performance/vitals/render
- https://developer.android.com/topic/performance/baselineprofiles/overview

## 11. 无障碍与舒适度

### 11.1 必须满足

- 最小触控目标 48dp。
- 正文对比度至少 4.5:1，大文字至少 3:1。
- TalkBack 能读取页面标题、和弦、指法、按钮状态和进度。

- 和弦名。
- 按法名。
- 起始品位。
- 六弦到一弦的 X/O/品位。

- 手指编号，如存在。

### 11.3 键盘与焦点

- 搜索 IME action 正确。
- BottomSheet 打开后焦点进入抽屉，关闭后返回触发元素。
- 错误字段关联错误文字。
- 预测返回取消后焦点不丢失。

## 16. 禁止事项

Codex 执行本方案时不得：

1. 一开始就删除旧前端。
2. 为了 Compose 重写乐理、识别、调度或 AI 校验算法。
3. 在 Composable 内创建 Repository、Store、播放器或网络 Provider。
4. 使用普通 Column 一次渲染全部和弦。
5. 用 UI delay 驱动节拍器或播放器。
6. 把 API Key 放入 UiState、日志、缓存或错误文本。
7. 使用 alpha/beta 依赖但不说明。
8. 为追求动效加入高成本模糊、大面积粒子或长期无限动画。
9. 只在 Debug 构建上判断性能。
10. 在没有设备/截图证据时宣称视觉完美。
11. 无视字体缩放和 TalkBack。
12. 修改应用包名、数据文件格式或版本号，除非用户另行要求。
13. 破坏现有 JPG、PNG、SVG 导出能力。
14. 删除仍被导出、测试或核心算法依赖的 Renderer。
15. 覆盖工作区中与本任务无关的未提交修改。

## 17. Codex 执行协议

2. 先执行 Phase 0，报告基线与工作区状态。
3. 建立阶段计划，一次只允许一个阶段处于进行中。
4. 每个阶段开始前列出预计新增/修改文件。
5. 优先使用现有核心，不复制算法。
6. 每完成一个可验证闭环就运行相关测试。
7. 每个阶段结束时更新本文件中相应复选框，或在独立实施报告中记录证据。

## 18. 完成定义

只有同时满足以下条件，才可宣布“前端重构完成”：

1. 第 12 节现有功能对齐清单全部完成。
2. P0 页面全部由 Compose 提供。
3. 旧 View 前端已无导航入口和运行时引用。
4. 现有核心测试、Lint、构建和新增 UI 测试通过。
5. 浅色、深色、200% 字体、TalkBack、预测返回通过。
6. 手机与展开布局都有真实视觉检查。
7. 核心动画按简化/关闭设置正确退化。
8. 性能指标有 release/profileable 测量证据。
9. AI 安全边界和离线能力未退化。
10. README 与实现报告已同步新版架构和操作说明。

如果其中任何一项缺失，应说明“当前完成到哪个 Phase”，而不是笼统宣称全部完成。
