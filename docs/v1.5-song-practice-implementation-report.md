## 3. Stage 0：V1.4 可信练习加固

### 3.1 单步去重

`PracticeSessionViewModel` 以真实播放状态中的循环/步骤/单调时钟锚点形成 step token；`PracticeGateway` 再以 `sessionId + stepToken` 派生稳定 UUID。`TransitionAttemptStore.read(id)` 在写入前检查已有结果，因此同一真实播放步骤即使快速重复点击也只记录一次；进入新锚点后才允许下一次结果。

### 3.2 竞态串行化

`recordAttempt`、`finish`、`reset` 与 `abandon` 通过 ViewModel 的 `Mutex`、pending job、generation 和独占动作串行化：

- 完成会等待在途 attempt 落盘后再保存汇总；
- reset/abandon 会使旧 generation 失效并清理会话 attempt；
- 旧异步写入不能在清理后回灌；
- 放弃效果只在清理完成后发出；
- UI 在 recording 期间不会产生第二个互斥终止动作。

### 3.3 完整续练配置

新增 `LastPracticeConfig` 与 `last-practice-config-v1.bin`（schema 1），保存模式、和弦列表、计划时长、BPM、拍号、切换方式、首拍重音、是否允许横按、最高品位、来源进行和是否沿用进行节奏。它与统计型 `PracticeSession` 分离，并使用现有原子写入和 `.bak` 回退。

`TransitionAttemptStore` 从 schema 1 升至 2，新增可空 `songId`、`sectionId`；旧数据读取时使用空来源，文件名保持 `transition-attempts-v1.bin`。

## 4. 数据模型

| 模型 | 核心内容 |
| --- | --- |
| `SongProject` | schema/parser 版本、稳定 ID、曲名/作者、完整 `originalText`、原调、移调、capo、BPM、拍号、节奏状态、段落、备注、升降号偏好和时间戳 |
| `SongSection` | 稳定 ID、保留的原始段落名、标准段落类型、顺序、重复次数和行 |
| `SongRow` | 稳定 ID、歌词、原始和弦行、和弦事件和顺序 |
| `SongChordEvent` | 稳定 ID、原符号/规范符号、字符位置、可空拍数、固定指法 ID、所在小节和顺序 |
| `SongPracticeRun` | 稳定 ID、song/section、`GUIDED_TRANSITION`/`PERFORMANCE`、BPM、移调、capo、起止时间、真实时长、完成状态、用户困难点、循环/显示设置和固定指法快照 |
| `UserReportedDifficulty` | 稳定 ID、song/section、方向性 from/to、报告时间、解决状态和备注 |

模型层验证稳定/重复 ID、唯一顺序、文本长度、数量、BPM、移调、capo、拍号、时间戳和 duration 范围。单项目上限为 200,000 字符、200 段、5,000 行和 20,000 个和弦事件；总项目上限 1,000，练习记录和困难标记各 100,000。

困难标记与 `TransitionAttempt` 严格分离：连续演奏后用户勾选的是主观困难点，不会变成正式失败；未勾选的切换也不会被当成成功。

## 6. 曲谱解析器

`SongSheetParser` 是独立、确定性、可做 JVM 测试的逻辑层，通过 `RepositorySongChordResolver` 复用 `ChordRepository`，而不是在 Composable/ViewModel 中复制和弦正则或乐理规则。

支持格式：

1. 行内和弦：`[C]歌词[G]歌词`；
2. 对齐和弦行 + 下一行歌词；
3. 纯和弦/小节：`| C | G | Am | F |`、同小节多和弦。

支持中文方括号/书名括号标题、`主歌/副歌/前奏/间奏/桥段/尾奏`，以及 `Verse 1`、`Pre-Chorus`、`Chorus`、`Bridge`、`Intro`、`Interlude`、`Solo`、`Outro`；未知标题保留原名并归为 `CUSTOM`。

正式和弦必须经本地核心规范化，覆盖普通/扩展和弦、slash chord、别名、`#`/`b` 与 Unicode `♯`/`♭`。未知的和弦形 token（如 `H7`、`Aminn`）保留在原行并进入 `unrecognizedTokens` 与警告。

英文歌词保护不是只看单个 `A/C/D` 字母：分类同时考虑 token 中有效和弦比例、小节线/重复符号、自然语言词数、空格结构、连续歌词上下文和置信度。低置信内容进入警告；导入预览可以逐行覆盖为 `AUTO`、`CHORDS`、`LYRICS`、`SECTION_TITLE` 或 `TEXT`，重新解析的稳定 ID 由内容/位置确定，原始文本不被覆盖。覆盖规则随导入草稿跨进程保存。

## 7. 时间与节奏语义

- `UNTYPED`：事件拍数保持 `null`；允许查看、移调、手动滚动/选段/切换和专项练习，不宣称精确拍位、高亮或自动同步。连续演奏使用手动前后步骤，节拍器只提供速度参照。
- `SIMPLE_MEASURES`：仅对明确小节线使用确定性规则。一个和弦占整小节；两个/四个和弦在 4/4 下分别为 2/1 拍；3/4、6/8 使用拍号分子平均分配。推断值在编辑页可见并可修改。
- `EXPLICIT_BEATS`：只有所有事件都有正的 `durationBeats` 才成立；支持常用和自定义拍数，可靠时才由 `ProgressionTransport` 驱动当前/下一和弦、节拍与完整段落播放。

歌词空格从不用于伪造精确时间。当前练习页以当前歌词行、当前/下一和弦和拍号状态同步展示，没有另建第二套音频或节拍调度器。

## 8. 页面、编配与两种练习模式

曲谱入口位于既有“练习”主页，没有增加第六个底部导航。新增曲谱库、导入、解析预览、详情、编辑和连续演奏页面；删除、覆盖、离开未保存编辑和放弃练习都有确认流程。导入解析与 Store IO 在 Gateway 的 IO dispatcher 执行，Composable 不直接读写文件。

编配复用 `ChordTransposer`、`CapoAssistant`、`ChordRepository`、熟悉/收藏指法和方向性 attempt：

- 移调范围 `-11…+11`，capo `0…12`；
- slash bass 与升降号偏好随整体移调；
- 明确显示实际听到的调、手型调和 capo；
- 最多三个确定性 capo 方案，说明横按数、陌生和弦、最高品位、熟练度与难度原因；
- 新手优先开放、非横按、低把位和熟悉指法；专业模式提供全部本地指法；
- 每个事件可固定指法，缺失时显示警告并回退本地推荐；项目和上次练习都保存该选择。

`GUIDED_TRANSITION` 复用现有练习会话和“跟上了/没跟上”。曲谱按真实顺序、段落重复和循环边界抽取方向性切换，连续相同和弦不生成 `C → C`；只练一对时 Gateway 还会验证该方向确实相邻或属于循环边界。每个真实 step token 最多写一次 `TransitionAttempt`，并带 song/section 来源，继续参与全局 `C → G`、`G → C` 分离统计。

`PERFORMANCE` 复用 `ProgressionTransport` 和绝对单调时钟，不要求每个切换点成功/失败。保存内容仅为真实时长、完成状态、BPM、移调/capo、循环/显示、固定指法快照和用户主动勾选的困难切换；不生成成功率，不将全部切换视为成功，也不把困难标记写为正式失败。

## 9. 首页、计划和成长数据

`LearningGoal.SONG_ACCOMPANIMENT` 只有在被选择时才启用曲谱任务，并按以下确定性优先级生成：最近曲谱续练、最近主动困难、曲谱中至少五个可信样本的全局弱切换、未练段落、未熟悉和弦、已完成/稳定段落。首页曲谱任务排在通用今日计划前。

继续入口恢复曲谱、段落、模式、BPM、移调、capo、固定指法历史快照、循环和指板显示；ViewModel 的 SavedState 还恢复练习 UUID、步骤、计时、复盘勾选和显示状态，避免旋转/进程重建产生重复 run。

曲谱成长看板使用正式 Store 的真实数据计算总时长、近 7 天时长、各段次数、最近 BPM、最高完成 BPM、未解决/已解决困难、未练段落、最近完整演奏和完成次数。连续演奏不显示或推导成功率。

## 11. 体验模式、可访问性与性能约束

新增能力集中在 `ExperienceCapabilities`：新手隐藏复杂曲谱理论、只显示一个 capo 简化方案、先显示最多六个指法事件并折叠高级节奏编辑；专业模式显示原调/手型调/实际调、三个方案、全部指法与默认展开的高级编辑。原有低 BPM、禁止横按、最高 5 品等新手默认仍生效。

曲谱页面使用可滚动/惰性布局、48–56dp 控件、600dp 分栏条件和不截断的多行文本。当前段落、当前和弦和下一和弦有显式 `contentDescription`，当前状态同时用文字而非只靠颜色表达。新增 AndroidTest 覆盖新手/专业、深色、200% 字体、横屏和 TalkBack 语义；本轮只完成编译，运行验证受无设备限制。

长文本解析、保存、导入、备份/恢复、批量编配、capo 方案和统计都在 IO dispatcher 执行；输入数量和文本长度在模型/Store/解析边界拒绝，避免无限数据进入主线程或内存。

## 17. 中间失败、重试与环境限制

- 一次阶段性测试在 Windows 锁住 Gradle `classes.jar` 时未进入测试；停止 daemon 后同一组测试重跑通过。它是构建环境文件锁，不是断言失败。
- 首次 ADB 探测包装脚本把单个路径当字符串索引，误尝试执行 `C`；修正为强制数组后找到 SDK ADB 并得到空设备列表。这不是应用测试结果。
- 首次 Release 因硬编码 Baseline Profile 自动采集触发无设备任务而失败；代码修复属性读取后，同一命令成功。失败没有被最终成功覆盖或省略。
- `docs/任务书.docx` 的文字已完整提取；本机没有可用 LibreOffice，且文档分页信息不足，未完成 Word 页面级渲染复核。任务书正文读取不受影响。
- 无设备：没有 connected runner 结果；200% 字体、TalkBack、深色、横屏、旋转/进程恢复和端到端曲谱交互只有代码与已编译测试覆盖。
- 无物理设备：没有中端 4 GB RAM、高刷新率、真实扬声器延迟、触觉和帧性能结论。
- 没有用户 AI 服务/密钥，也没有进行在线 AI 测试；V1.5 正式曲谱数据不依赖 AI。
