# 吉他和弦学习软件需求规格说明书

文档版本：1.4
当前实现版本：Android V1.4
日期：2026-07-13
状态：Android V1.4 实现同步稿；V1.4 的原始、唯一需求与验收依据为 `docs/任务书.docx`

## 1. 引言

### 1.1 编写目的

本文档用于描述吉他和弦学习软件的功能需求、数据需求、非功能需求、边界限制与验收标准，供产品评审、开发实现、测试验收和后续维护参考。

本文档仅描述系统应具备的能力和可验证结果，不规定具体技术栈、系统架构、数据库结构、第三方库选型或核心算法实现。

### 1.2 产品背景

吉他学习者在学习和弦时，通常需要同时理解和弦名称、组成音、和弦性质、吉他按法、指板位置以及实际听感。若这些信息分散在不同资料中，初学者容易只记住手型而缺少乐理理解；有一定基础的学习者也难以快速比较不同和弦类型和不同把位的声音差异。

本软件以“和弦字典”为核心，为用户提供一个可以查询、理解、查看和试听吉他和弦的工具型学习环境。

### 1.3 产品范围

本软件的核心范围包括：

- 根据用户输入的和弦名称显示和弦信息。
- 展示和弦组成音、和弦类型和性质说明。
- 展示常见吉他按法和对应指板示意图。
- 提供基于 MIDI/SoundFont 的和弦声音预览。
- 对错误输入、未知和弦、无可用按法等情况给出清晰提示。
- 使用真实学习资料与本地历史安排今日练习，逐次记录“跟上了”和“没跟上”。
- 对方向性和弦切换计算可信统计、难度建议和长期成长信息。
- 提供真正影响页面信息密度与练习默认值的新手/专业体验模式。
- 在不包含 API Key 的前提下完整备份与恢复用户本地数据。

本软件不以 MIDI 生成音乐为主要功能。MIDI/SoundFont 仅用于和弦声音试听，帮助用户理解不同和弦之间的听感差异。

### 1.4 术语说明

| 术语 | 说明 |
| --- | --- |
| 和弦 | 多个音按照一定音程关系同时或近似同时发声形成的声音组合。 |
| 根音 | 和弦名称中表示基础音高的音名，如 C、D、F#、Bb。 |
| 和弦类型 | 表示和弦结构和性质的类别，如大三和弦、小三和弦、属七和弦、挂留和弦等。 |
| 组成音 | 构成某个和弦的音名集合。 |
| 音程结构 | 和弦内各音相对于根音的音程关系。 |
| 吉他按法 | 在吉他六根弦上的具体按弦、空弦和闷弦方式。 |
| 指板示意图 | 用图形方式展示弦、品位、按弦点、空弦和闷弦状态的视图。 |
| MIDI/SoundFont | 用于播放和弦试听音色的声音预览方式，在本软件中不承担编曲或音乐生成职责。 |

## 2. 产品概述

### 2.1 产品定位

本软件是一款面向吉他学习者的工具型软件。软件以和弦查询和理解为核心，不定位为编曲软件、录音软件、MIDI 创作软件或完整音乐制作软件。

本软件首版形态为 Android 移动端应用。HarmonyOS、iOS、网页端和桌面端不属于首版实现范围，可作为后续版本扩展方向。

### 2.2 产品目标

- 帮助用户通过输入和弦名称快速获得该和弦的核心信息。
- 帮助用户把乐理中的和弦结构与吉他指板上的实际按法对应起来。
- 帮助用户通过声音试听建立不同和弦类型之间的听感记忆。
- 支持后续扩展更多根音、和弦类型、转位、把位和调弦。

### 2.3 用户角色

| 用户角色 | 描述 | 主要诉求 |
| --- | --- | --- |
| 初学者 | 正在学习基础和弦、开放和弦和常见歌曲伴奏的用户。 | 快速知道某个和弦怎么按、由哪些音组成、听起来是什么感觉。 |
| 有一定基础的学习者 | 已掌握部分常见和弦，希望学习更多和弦类型、把位和乐理关系的用户。 | 比较不同和弦类型、查看多个按法、理解和弦结构和声音差异。 |
| 内容维护者 | 负责维护和弦数据、按法数据或说明内容的人员。 | 确保和弦信息准确、按法可用、说明清晰且便于扩展。 |

### 2.4 典型使用场景

- 用户在学习歌曲时遇到 “Fmaj7”，输入和弦名称后查看组成音、类型说明、常见按法和指板示意图。
- 初学者输入 “G” 后，查看开放和弦按法，并点击试听按钮确认该和弦的整体听感。
- 有基础的学习者输入 “Bm7”，比较不同把位的按法，理解小七和弦的组成音和声音特点。
- 用户输入拼写错误或暂不支持的和弦名称时，系统给出明确反馈，避免用户误以为软件无响应。
- 用户查询扩展和弦时，系统在已有数据或规则可支持的范围内展示结果；无法支持时，系统说明当前限制。

### 2.5 首版 MVP 范围

为避免首版功能范围过大，系统第一版应优先完成“可查询、可查看、可试听、可理解”的核心闭环。首版不追求覆盖所有理论上存在的和弦和所有可能按法，而应优先覆盖学习者最常见、最容易使用、最便于验证的内容。

首版 MVP 范围如下：

- 默认支持六弦吉他标准调弦，即 E、A、D、G、B、E。
- 默认支持十二平均律中的常见根音表示，包括 C、C#、Db、D、D#、Eb、E、F、F#、Gb、G、G#、Ab、A、A#、Bb、B。
- 首版至少支持以下常见和弦类型：大三和弦、小三和弦、属七和弦、大七和弦、小七和弦、挂留和弦、减和弦、增和弦和加音和弦。
- 首版至少覆盖 C、D、E、F、G、A、B、Am、Dm、Em、G7、A7、E7、Cmaj7、Fmaj7、Am7、Dm7、Bm7、Csus2、Dsus4、Bdim、Caug、Cadd9 等常见查询对象。
- 每个已支持的常见和弦应至少提供一个推荐吉他按法。
- 对于 C、D、E、G、A、Am、Dm、Em、G7 等基础和弦，应优先提供开放和弦按法。
- 对于 F、Bm、Bm7 等常见封闭和弦，应允许提供封闭和弦或简化按法。
- 首版应至少支持和弦查询、组成音展示、和弦类型说明、指板示意图展示和声音试听。
- 首版目标平台为 Android。
- 首版暂不要求支持用户自定义调弦。
- 首版暂不要求支持左手琴、七弦吉他、贝斯、尤克里里或其他乐器。
- 首版暂不要求自动生成所有理论可行按法。
- 首版暂不要求提供 MIDI 文件导入、MIDI 文件导出、音频导出或完整编曲功能。
- 首版暂不要求支持 iOS、网页端或桌面端。

### 2.6 用户操作流程

系统的基础使用流程如下：

1. 用户打开软件首页。
2. 系统显示和弦名称输入框、查询按钮和基础使用提示。
3. 用户输入需要查询的和弦名称，例如 C、Am、G7、Fmaj7。
4. 用户点击查询按钮，或通过回车触发查询。
5. 系统识别用户输入的和弦名称。
6. 如果识别成功，系统进入和弦结果展示区域。
7. 系统显示该和弦的标准名称、根音、和弦类型、组成音和音程结构。
8. 系统显示该和弦的文字说明，包括基本性质、常见听感和学习提示。
9. 系统显示一个或多个常见吉他按法。
10. 系统根据当前选中的按法显示对应的指板示意图。
11. 用户可以点击试听按钮，听到当前和弦或当前按法对应的声音预览。
12. 如果同一和弦存在多个按法，用户可以切换不同按法进行查看和试听。
13. 如果输入无法识别，系统显示错误提示，并给出示例输入。
14. 如果和弦存在但按法暂缺，系统仍应展示已知和弦信息，并提示按法数据暂缺。
15. 如果试听功能不可用，系统仍应展示和弦信息和按法信息，并提示声音试听暂不可用。

### 2.7 页面与模块划分

首版软件可划分为以下主要页面或功能区域。

#### 2.7.1 首页 / 查询页

首页应包含以下内容：

- 软件名称或标题。
- 和弦名称输入框。
- 查询按钮。
- 示例输入提示，例如 C、Am、G7、Fmaj7。
- 简短说明，告诉用户本软件用于查询吉他和弦的组成音、按法和听感。

#### 2.7.2 和弦结果展示区

和弦结果展示区应包含以下内容：

- 和弦标准名称。
- 根音。
- 和弦类型。
- 组成音。
- 音程结构。
- 和弦类型说明。
- 常见听感或学习提示。
- 按法列表。
- 当前按法的指板示意图。
- 试听按钮。
- 异常或缺失数据提示。

#### 2.7.3 按法切换区

当同一和弦存在多个按法时，系统应提供按法切换能力。按法切换区应显示：

- 按法名称或把位说明。
- 当前按法难度，如入门、常见、进阶。
- 当前按法是否为推荐按法。
- 当前按法对应的起始品位。
- 当前按法是否包含封闭横按。
- 当前按法是否包含空弦或闷弦。

#### 2.7.4 异常提示区

异常提示区应处理以下情况：

- 输入为空。
- 输入格式错误。
- 输入内容无法识别。
- 当前和弦暂不支持。
- 当前和弦存在，但缺少按法数据。
- 当前和弦存在，但试听功能不可用。
- 当前音色资源加载失败。
- 当前指板图无法正常显示。

## 3. 功能需求

### 3.1 和弦名称输入与识别

- FR-01：系统应提供和弦名称输入入口，允许用户输入需要查询的和弦名称。
- FR-02：系统应识别由根音和和弦类型组成的常见和弦名称。
- FR-03：系统应支持自然音、升号音和降号音作为根音表示。
- FR-04：系统应支持常见和弦类型的查询，包括但不限于大三和弦、小三和弦、七和弦、大七和弦、小七和弦、挂留和弦、减和弦、增和弦、加音和弦和扩展和弦。
- FR-05：系统应对常见等价写法或别名给出一致的识别结果。
- FR-06：系统应在用户输入为空、格式错误、含义模糊或暂不支持时给出明确提示。
- FR-07：系统应避免将无法识别的输入误判为有效和弦。
- FR-07-1：系统应支持用户输入大小写混合的和弦名称，并将其规范化为统一格式。
- FR-07-2：系统应支持常见和弦别名识别，例如 maj7 与 M7、min 与 m、dim 与 °、aug 与 +。
- FR-07-3：系统应在识别用户输入后显示标准化后的和弦名称，避免用户混淆。
- FR-07-4：系统应对容易混淆的输入给出提示，例如 H、Cb、E# 等特殊或非常见写法。
- FR-07-5：系统应提供至少 3 个可点击或可复制的示例输入，帮助初学者理解输入格式。

### 3.2 和弦信息总览

- FR-08：系统应在成功识别和弦后显示该和弦的标准名称。
- FR-09：系统应显示该和弦的根音。
- FR-10：系统应显示该和弦所属的和弦类型。
- FR-11：系统应显示该和弦的组成音。
- FR-12：系统应显示该和弦的常见吉他按法。
- FR-13：系统应显示与当前按法对应的指板示意图。
- FR-14：系统应提供该和弦的声音试听入口。

### 3.3 组成音展示

- FR-15：系统应展示和弦的组成音名称。
- FR-16：系统应展示组成音与根音之间的音程关系。
- FR-17：系统应保证组成音信息与当前识别的和弦名称一致。
- FR-18：系统应在存在异名同音表达时使用一致、清晰的音名显示方式。
- FR-19：系统应支持后续扩展更多和弦类型的组成音展示。

### 3.4 和弦类型与性质说明

- FR-20：系统应展示当前和弦类型的名称。
- FR-21：系统应用学习者可理解的语言说明该和弦类型的基本性质。
- FR-22：系统应说明该和弦类型的典型听感或音乐功能，但不得把主观描述作为唯一信息来源。
- FR-23：系统应区分不同和弦类型之间的结构差异。
- FR-24：系统应在无法提供完整说明时明确标识当前说明缺失或待补充。

### 3.5 常见吉他按法展示

- FR-25：系统应展示当前和弦的一个或多个常见吉他按法。
- FR-26：系统应展示每个按法涉及的弦、品位、空弦和闷弦信息。
- FR-27：系统应在适用时展示推荐指法。
- FR-28：系统应支持同一和弦存在多个把位或多个常见按法。
- FR-29：系统应允许用户在同一和弦的多个按法之间切换查看。
- FR-30：系统应在某个和弦暂无可用吉他按法时给出明确提示。
- FR-31：系统应优先展示适合学习者理解和练习的常见按法。

### 3.6 指板示意图展示

- FR-32：系统应为当前选择的吉他按法展示对应的指板示意图。
- FR-33：系统应在指板示意图中清楚区分六根弦和相关品位。
- FR-34：系统应在指板示意图中标识按弦位置。
- FR-35：系统应在指板示意图中标识空弦和闷弦状态。
- FR-36：系统应在需要时展示当前图示对应的起始品位或品位范围。
- FR-37：系统应保证指板示意图与文字形式的按法数据一致。
- FR-38：系统应支持后续扩展不同调弦或不同弦数的指板展示需求。

### 3.7 声音试听

- FR-39：系统应提供和弦声音试听按钮或等价操作入口。
- FR-40：系统应在用户触发试听后播放当前和弦对应的声音预览。
- FR-41：系统应使用 MIDI/SoundFont 相关能力实现和弦声音预览。
- FR-42：系统应保证试听内容与当前显示的和弦信息一致。
- FR-43：当用户选中了某个具体吉他按法时，系统应优先播放该按法在当前调弦下对应的实际弦音。
- FR-44：当当前按法数据缺失或无法生成实际弦音时，系统可退化为播放该和弦的基础组成音。
- FR-45：系统应区分“组成音试听”和“当前按法试听”，避免用户误解二者完全相同。
- FR-46：系统应让用户能够感知当前试听正在播放、已结束或不可播放。
- FR-47：系统应在声音资源不可用或播放失败时给出明确提示。
- FR-48：系统应避免把试听功能扩展为 MIDI 编曲、音乐生成、录音或音频导出功能。
- FR-49：系统应支持后续调整试听音色、播放时长或播放方式，但这些能力不属于核心编曲功能。
- FR-50：系统应避免在未获得用户操作的情况下自动播放声音，防止影响用户体验。
- FR-51：系统应在切换按法后同步更新试听内容，使试听结果与当前显示的指板示意图保持一致。

### 3.8 异常与反馈

- FR-52：系统应在用户输入错误和弦名称时提示输入格式或识别失败原因。
- FR-53：系统应在和弦存在但缺少按法数据时展示已有和弦信息，并提示按法暂缺。
- FR-54：系统应在和弦存在但无法试听时展示已有和弦信息，并提示试听暂不可用。
- FR-55：系统应避免因单项信息缺失导致整个查询结果不可用。
- FR-56：系统应在加载、查询或播放过程中提供必要的状态反馈。

### 3.9 可扩展需求

- FR-57：系统应支持后续扩展全部十二平均律根音及其常见异名写法。
- FR-58：系统应支持后续扩展更多和弦类型、转位、分数和弦和高阶扩展和弦。
- FR-59：系统应支持后续扩展更多吉他把位、封闭和弦、开放和弦和替代按法。
- FR-60：系统应支持后续扩展不同调弦场景下的和弦按法展示。
- FR-61：系统应支持对和弦数据和按法数据进行持续维护和补充。

## 4. 数据需求

### 4.1 和弦基础数据

系统应维护或生成以下和弦基础信息：

- 和弦标准名称。
- 和弦可识别名称或别名。
- 根音。
- 和弦类型。
- 音程结构。
- 组成音。
- 和弦类型说明。
- 典型听感或学习提示。

### 4.2 吉他按法数据

系统应维护或生成以下吉他按法信息：

- 所属和弦。
- 按法名称或把位说明。
- 每根弦对应的状态，包括按弦、空弦或闷弦。
- 每根弦对应的品位信息。
- 可选的手指编号或推荐指法。
- 当前按法适用的调弦。
- 当前按法适用的品位范围。
- 当前按法是否为常见或推荐按法。

### 4.2.1 按法数据生成与维护原则

吉他按法数据应优先采用经过验证的常见按法，不应仅凭理论音高匹配自动生成并直接标记为推荐按法。

系统可以通过规则、算法或数据表生成候选按法，但推荐按法应满足以下条件：

- 按法在常见吉他学习资料或实际演奏中具有合理性。
- 按法在人体手型上具有可操作性。
- 按法不应包含明显不合理的大跨度指法。
- 按法不应错误包含不属于当前和弦的关键音。
- 按法如果省略某些组成音，应在数据中明确标识。
- 按法如果包含重复音，应允许存在，但试听和指板图应与实际弦音一致。
- 按法如果属于简化按法，应明确标记为“简化按法”。
- 按法如果属于封闭和弦，应明确标记是否需要横按。
- 未经过验证的候选按法不得标记为“推荐按法”。

### 4.2.2 按法数据字段建议

每个吉他按法数据至少应包含以下字段：

- 和弦名称。
- 标准和弦名称。
- 调弦。
- 弦数。
- 每根弦的状态。
- 每根弦对应的品位。
- 每根弦对应的推荐手指编号。
- 是否为推荐按法。
- 是否为简化按法。
- 是否包含横按。
- 起始品位。
- 显示品位范围。
- 难度等级。
- 按法说明。
- 当前按法实际发出的音名。
- 当前按法实际发出的 MIDI 音高。

### 4.3 指板示意图数据

系统应具备展示指板示意图所需的数据口径：

- 弦数。
- 调弦。
- 起始品位。
- 显示品位范围。
- 每根弦的按弦位置。
- 空弦标记。
- 闷弦标记。
- 可选的指法标记。

### 4.4 声音试听数据

系统应具备播放和弦试听所需的数据口径：

- 当前和弦对应的 MIDI 音高。
- 各组成音的播放顺序或同时播放关系。
- 试听播放时长。
- 试听音色。
- 播放状态。
- 播放失败状态。

### 4.5 数据准确性要求

- DR-01：系统应保证同一和弦的名称、组成音、类型说明、按法和试听音高之间相互一致。
- DR-02：系统应保证指板示意图与按法数据一致。
- DR-03：系统应避免把未验证的按法标记为推荐按法。
- DR-04：系统应允许对和弦数据、按法数据和说明内容进行后续补充与修正。
- DR-05：系统应在数据缺失时明确展示缺失状态，而不是展示错误或误导性信息。

## 5. 非功能需求

### 5.1 易用性

- NFR-01：系统应让用户无需理解复杂乐理术语即可完成基础和弦查询。
- NFR-02：系统应让初学者能够快速分辨按弦、空弦和闷弦。
- NFR-03：系统应让有一定基础的用户能够比较同一和弦的不同按法。
- NFR-04：系统应使用清晰、一致的中文术语描述和弦信息。

### 5.1.1 初学者友好要求

- NFR-04-1：系统应避免在核心界面中堆叠过多复杂术语。
- NFR-04-2：系统应在出现专业术语时提供简短解释，例如根音、三度音、五度音、闷弦、空弦。
- NFR-04-3：系统应使用统一符号表达空弦和闷弦，例如 O 表示空弦，X 表示闷弦。
- NFR-04-4：系统应在指板示意图附近显示文字版按法，帮助用户把图形和文字对应起来。
- NFR-04-5：系统应优先展示适合初学者的常见按法，再展示进阶按法。
- NFR-04-6：系统应在必要时提示用户“该按法可能需要横按，初学者会觉得较难”。

### 5.2 准确性

- NFR-05：系统展示的组成音、音程关系、按法和试听音高应保持音乐理论上的一致性。
- NFR-06：系统不应在缺少数据依据时展示确定性结论。
- NFR-07：系统应对别名、升降号和异名同音等情况保持一致处理。

### 5.3 响应性

- NFR-08：系统应在用户提交查询后及时返回可见反馈。
- NFR-09：系统应在试听触发后及时反馈播放状态。
- NFR-10：系统应在数据加载或声音资源准备过程中避免界面无响应。

### 5.4 可访问性

- NFR-11：系统应避免仅依赖颜色表达按弦、空弦、闷弦或错误状态。
- NFR-12：系统应为关键文本和操作提供清晰可读的表达。
- NFR-13：系统应保证主要功能可被键盘或等价输入方式访问。

### 5.5 可维护性

- NFR-14：系统应允许后续扩展和弦类型、按法数据、调弦数据和说明内容。
- NFR-15：系统应保持和弦数据、按法数据、指板展示数据和试听数据之间的对应关系可检查。
- NFR-16：系统应便于对错误和弦数据进行修订。

## 6. 边界与限制

### 6.1 范围内能力

- 和弦名称查询。
- 和弦组成音展示。
- 和弦类型和性质说明。
- 常见吉他按法展示。
- 指板示意图展示。
- 和弦声音试听。
- 错误、未知和缺失数据提示。
- 和弦数据和按法数据的后续扩展。
- 收藏、历史、自定义/熟悉指法与和弦进行。
- 离线练习、节拍器、方向性切换统计、难度建议与成长看板。
- 首次启动学习档案、动态今日练习、新手/专业模式。
- 本地完整备份、校验、预览、合并或覆盖恢复。

### 6.2 范围外能力

以下能力不属于本软件核心范围：

- MIDI 编曲。
- 自动生成完整音乐作品。
- 多轨音乐制作。
- 音频录制。
- 音频编辑。
- 音频或 MIDI 文件导出。
- 乐谱排版。
- 自动伴奏生成。
- 完整吉他调音器。
- 社区发布、评论或社交互动。

### 6.3 限制说明

- 系统可以使用 MIDI/SoundFont 实现和弦试听，但试听功能仅用于学习和理解和弦听感。
- 系统可以展示多个按法，但不要求为每个理论上存在的和弦提供所有可能按法。
- 系统可以支持扩展和弦，但在数据或规则尚未覆盖时应明确提示当前不支持。
- 系统可以支持后续扩展其他调弦，但默认需求应至少覆盖常见六弦吉他标准调弦场景。

### 6.4 当前版本不处理的复杂情况

V1.4 不要求处理以下复杂情况：

- 不要求自动判断某个和弦在具体歌曲中的功能。
- 不要求分析调性、级数或和声进行。
- 不要求根据用户上传音频识别和弦。
- 不要求根据用户哼唱或录音识别和弦。
- 不要求根据 MIDI 文件自动识别完整和弦进行。
- 不要求生成伴奏。
- 不要求生成旋律。
- 不要求支持扫弦节奏型教学。
- 不要求支持拨片、指弹或分解和弦教学。
- 不要求支持动态演奏姿势识别。
- 不要求支持摄像头识别用户按法是否正确。
- 不要求支持用户账号或云同步；收藏、历史及其他用户数据仅保存在本机并可手动备份。
- 不要求支持多语言界面。
- 不要求支持 HarmonyOS、iOS、网页端和桌面端适配；当前版本以 Android 为目标平台。

## 7. 验收标准

### 7.1 核心功能验收

- AC-01：输入常见和弦名称后，系统能显示标准名称、根音、和弦类型、组成音、至少一个常见按法和对应指板示意图。
- AC-02：输入常见和弦名称后，用户能触发试听并听到与当前和弦组成音一致的声音预览。
- AC-03：输入扩展和弦名称后，系统能在已支持范围内显示对应结果；暂不支持时，系统能给出明确提示。
- AC-04：同一和弦存在多个常见按法时，用户能查看并切换不同按法。
- AC-05：用户输入非法、空白或含义模糊的和弦名称时，系统能给出清晰提示。
- AC-06：当某个和弦缺少按法数据时，系统能展示已有和弦信息，并明确提示按法暂缺。
- AC-07：当声音试听不可用时，系统能展示已有和弦信息，并明确提示试听暂不可用。
- AC-08：试听功能不应提供 MIDI 编曲、自动生成音乐、录音或导出能力。

### 7.1.1 具体验收用例

#### 用例 1：查询 C 和弦

- 输入：C
- 预期结果：系统识别为 C 大三和弦；显示根音 C、和弦类型大三和弦、组成音 C/E/G；显示至少一个常见开放 C 和弦按法及对应指板示意图；可以播放 C 和弦试听；试听内容应与当前显示的组成音或当前按法实际弦音一致。

#### 用例 2：查询 Am 和弦

- 输入：Am
- 预期结果：系统识别为 A 小三和弦；显示根音 A、和弦类型小三和弦、组成音 A/C/E；显示至少一个常见开放 Am 和弦按法及对应指板示意图；可以播放 Am 和弦试听。

#### 用例 3：查询 G7 和弦

- 输入：G7
- 预期结果：系统识别为 G 属七和弦；显示根音 G、和弦类型属七和弦、组成音 G/B/D/F；显示至少一个常见 G7 和弦按法及对应指板示意图；可以播放 G7 和弦试听。

#### 用例 4：查询 Fmaj7 和弦

- 输入：Fmaj7
- 预期结果：系统识别为 F 大七和弦；显示根音 F、和弦类型大七和弦、组成音 F/A/C/E；显示至少一个常见 Fmaj7 和弦按法及对应指板示意图；可以播放 Fmaj7 和弦试听。

#### 用例 5：查询暂不支持的复杂和弦

- 输入：C13#11
- 预期结果：如果系统已支持该和弦，则显示对应和弦信息；如果系统暂不支持该和弦，则提示“当前版本暂不支持该和弦类型”；系统不得显示错误组成音；系统不得将该输入误判为其他和弦。

#### 用例 6：输入非法内容

- 输入：H13x
- 预期结果：系统提示无法识别该和弦名称；系统给出正确输入示例，例如 C、Am、G7、Fmaj7；系统不得进入错误结果页；系统不得展示伪造的和弦信息。

#### 用例 7：输入为空

- 输入：空白
- 预期结果：系统提示用户请输入和弦名称；系统不得执行无意义查询；系统不得出现程序报错或界面无响应。

#### 用例 8：和弦存在但按法缺失

- 输入：某个系统可识别但暂无按法数据的和弦。
- 预期结果：系统显示该和弦的标准名称、根音、类型、组成音和说明；系统提示“当前和弦暂无可用吉他按法”；系统不得因为按法缺失而隐藏全部和弦信息。

#### 用例 9：试听资源不可用

- 操作：用户点击试听按钮，但声音资源加载失败。
- 预期结果：系统提示“试听暂不可用”或类似信息；系统保留当前和弦信息和按法信息；系统不得出现界面卡死或无反馈状态。

#### 用例 10：切换同一和弦的不同按法

- 输入：C
- 操作：用户在多个 C 和弦按法之间切换。
- 预期结果：系统更新当前按法的文字说明、指板示意图和对应试听内容；系统不得出现文字按法、指板图和试听内容不一致的情况。

### 7.2 用户场景验收

- AC-09：初学者能够通过查询基础和弦理解该和弦的按法、组成音和声音效果。
- AC-10：有一定基础的学习者能够通过查询七和弦、挂留和弦或扩展和弦理解不同和弦类型的结构差异。
- AC-11：用户能够把同一和弦的文字按法与指板示意图对应起来。
- AC-12：用户能够通过试听比较不同和弦类型的听感差异。

### 7.3 文档验收

- AC-13：本文档应覆盖引言、产品概述、用户角色、使用场景、功能需求、数据需求、非功能需求、边界与限制和验收标准。
- AC-14：所有核心功能均应以可验证的“系统应”需求形式描述。
- AC-15：所有非目标功能均应在边界与限制中明确列出。
- AC-16：文档应同时覆盖初学者和有一定基础的吉他学习者两个主要用户群体。

### 7.4 MVP 验收标准

- AC-17：首版系统应至少支持六弦吉他标准调弦。
- AC-18：首版系统应至少支持 C、D、E、F、G、A、B、Am、Dm、Em、G7、A7、E7、Cmaj7、Fmaj7、Am7、Dm7、Bm7、Csus2、Dsus4、Bdim、Caug、Cadd9 等常见和弦。
- AC-19：首版系统应至少为 C、D、E、G、A、Am、Dm、Em、G7 提供常见开放和弦按法。
- AC-20：首版系统应至少为 F 或 Bm 类和弦提供一个可用封闭和弦或简化按法示例。
- AC-21：首版系统应能将文字按法数据正确转换为指板示意图。
- AC-22：首版系统应能播放至少一种可听辨的和弦试听音色。
- AC-23：首版系统应保证和弦名称、组成音、按法、指板图和试听内容之间不存在明显冲突。
- AC-24：首版系统应在输入错误、按法缺失、试听失败时提供明确提示。
- AC-25：首版系统不得提供 MIDI 编曲、自动生成完整音乐、录音或导出功能。

### 7.5 V1.4 学习闭环验收标准

- AC-26：首次启动应显示四步引导，记录学习水平、最多两个目标、每日练习时长和体验模式；跳过应生成安全默认档案，并可从“我的”重新设置。
- AC-27：每次点击“跟上了”或“没跟上”都应立即形成独立、可恢复的尝试记录；两者必须产生不同的成功/失败结果。
- AC-28：失败应把当前连续成功次数重置为 0，但不得降低此前最佳连续次数；成功率为成功次数除以总尝试次数。
- AC-29：旧版练习记录应迁移并保留可证实的历史字段，但不得因缺少逐次结果而被视为 100% 成功。
- AC-30：`C → G` 与 `G → C` 应作为不同方向分别统计；少于 5 个可信样本时不得给出熟练度或“最薄弱”判定。
- AC-31：首页今日练习应由本地学习档案、学习资料、收藏/熟悉状态及可信历史确定性生成；无足够数据时不得伪造薄弱项。
- AC-32：“继续上次练习”应直接恢复和弦、模式、BPM、拍号、切换方式、时长、品位/横按约束及来源进行节奏并开始；“调整”才进入设置页。
- AC-33：练习设置应提供最近、收藏、熟悉、推荐、保存进行和手动选材，以及 ±1/±5 BPM、常用速度、30/60/120/300 秒和自定义时长。
- AC-34：“弹唱准备”应使用已保存进行、70 BPM 和原进行每步拍数；“速度挑战”应使用熟悉和弦；没有所需真实资料时不得展示伪预设。
- AC-35：最近尝试不足 10 次时仅显示数据不足；达到阈值后按成功率和可比较练习给出保持、升 5 BPM 或降 5/10 BPM 的确定性建议。
- AC-36：新手模式应默认精简乐理、推荐指法、50 BPM、60 秒、禁用横按并限制至 5 品；专业模式应显示完整乐理和全部指法，默认 80 BPM、120 秒、允许横按至 24 品并展开高级设置。切换后页面应立即生效。
- AC-37：完整备份应包含界面设置、学习档案、收藏、带时间戳历史、自定义/熟悉指法、进行与草稿、练习会话和逐次尝试，不得包含 API Key。
- AC-38：恢复前应校验 ZIP 条目、大小、清单和 SHA-256，显示内容预览并要求确认；失败或取消应回滚，重复合并同一备份不得使练习统计翻倍。
- AC-39：恢复冲突应按数据类型处理：收藏并集、历史按时间取新且限制数量、自定义指法/进行保留本地并为冲突导入副本、练习会话/尝试按稳定 ID 去重；设置可选择不恢复。
- AC-40：成长看板应基于真实数据展示七日时长、尝试/成功/失败/成功率、连续练习天数、方向性强弱切换和稳定 BPM；缺失数据应显示空状态。
- AC-41：200% 系统字体、紧凑宽度和横屏下，关键页面及“跟上了/没跟上”操作应可达，不得通过强行缩小字体规避布局问题；关键结果按钮应具有可读语义。
- AC-42：AI 应保持默认关闭和可选，不能成为引导、首页推荐、练习、统计、难度建议、备份或恢复等核心离线能力的依赖。
- AC-43：Android 设备测试应覆盖引导、目标修改、直接继续、成功/失败/连续次数、模式差异、200% 字体、横屏、真实文档 URI 备份预览/确认和 Activity 重建；物理设备性能未实测时必须明确标记未完成。

## 10. 版本实现规划

本章节用于说明软件实现版本的功能优先级。这里的 V1.0、V1.1 指软件产品版本，不等同于本文档版本号。

### 10.1 V1.0 首版 MVP

V1.0 应优先完成“可查询、可查看、可试听、可理解”的核心闭环，使 Android 用户能够完成基础和弦学习任务。

V1.0 应实现以下需求：

- 平台范围：完成 Android 移动端应用的基础可用版本，不要求支持 HarmonyOS、iOS、网页端或桌面端。
- 查询入口：提供和弦名称输入框、查询按钮、回车查询和基础示例输入。
- 和弦识别：支持常见根音和首版 MVP 和弦清单，包括 C、D、E、F、G、A、B、Am、Dm、Em、G7、A7、E7、Cmaj7、Fmaj7、Am7、Dm7、Bm7、Csus2、Dsus4、Bdim、Caug、Cadd9。
- 信息展示：显示和弦标准名称、根音、和弦类型、组成音、音程结构、类型说明和学习提示。
- 按法展示：为每个已支持常见和弦至少提供一个推荐吉他按法；为 C、D、E、G、A、Am、Dm、Em、G7 优先提供开放和弦按法；为 F 或 Bm 类和弦提供封闭和弦或简化按法。
- 指板示意图：根据当前按法显示六弦吉他标准调弦下的指板示意图，并清楚标识按弦、空弦和闷弦。
- 声音试听：提供基于 MIDI/SoundFont 的和弦试听，播放内容应与当前和弦组成音或当前按法实际弦音一致。
- 异常反馈：处理空输入、非法输入、暂不支持和弦、按法缺失、试听失败等情况，并给出清晰提示。
- 范围边界：不提供 MIDI 编曲、自动生成完整音乐、录音、音频导出、MIDI 文件导入或 MIDI 文件导出能力。

V1.0 完成标准应至少满足 AC-01 至 AC-08、AC-17 至 AC-25。

### 10.2 V1.1 体验与数据增强版

V1.1 应在 V1.0 可用闭环基础上，提高输入容错、按法质量、试听一致性和初学者友好程度。

当前 Android 版本按本节作为实现范围；HarmonyOS、iOS、网页端和桌面端仍不进入本版本。

V1.1 应实现以下需求：

- 输入增强：支持大小写混合输入规范化，支持 maj7/M7、min/m、dim/°、aug/+ 等常见别名识别，并在识别后显示标准化和弦名称。
- 输入提示：对 H、Cb、E# 等容易混淆或非常见写法给出提示，并提供至少 3 个可点击或可复制的示例输入。
- 按法切换：支持同一和弦多个常见按法的切换展示，并显示按法名称、难度、是否推荐、起始品位、是否横按、是否包含空弦或闷弦。
- 试听增强：区分“组成音试听”和“当前按法试听”；切换按法后同步更新试听内容；按法数据缺失时允许退化为播放基础组成音。
- 数据质量：补充按法难度、简化按法、横按、实际发声音名、实际 MIDI 音高等数据字段，并确保未验证候选按法不得标记为推荐按法。
- 初学者友好：在核心界面避免堆叠复杂术语，为根音、三度音、五度音、空弦、闷弦等术语提供简短解释；统一使用 O 表示空弦、X 表示闷弦。
- 提示完善：在横按或较难按法附近给出难度提示，帮助初学者理解练习难点。
- 验收补充：覆盖 7.1.1 中列出的 C、Am、G7、Fmaj7、复杂和弦、非法输入、空输入、按法缺失、试听失败和按法切换等具体验收用例。

V1.1 完成标准应在继续满足 V1.0 验收标准的基础上，重点满足 FR-07-1 至 FR-07-5、FR-43 至 FR-51、4.2.1、4.2.2、5.1.1 和 7.1.1 的要求。

### 10.3 V1.2 收藏与内容扩展版

V1.2 继续只面向 Android，不开发 HarmonyOS、iOS、网页端或桌面端。本版本在 V1.1 基础上增加轻量学习辅助能力，让用户更容易回到常用和弦和最近查询内容。

V1.2 应实现以下需求：

- 收藏常用和弦：用户可将当前查询到的和弦加入收藏，也可取消收藏。
- 最近查询：系统应保存最近查询过的和弦，并允许用户通过最近查询快速再次打开。
- 本地持久化：收藏和最近查询应保存在本机，下次打开应用后仍可查看。
- 更多和弦：新增常见属七、小三、九和弦和分数和弦，例如 C7、D7、Bm、F#m、C9、G9、D9、A9、C/E、G/B、D/F#。
- 更多按法：为新增和弦提供至少一个可用按法；对于 Bm 等常见较难和弦，应提供简化按法或明确难度提示。
- 输入扩展：系统应支持常见分数和弦输入，例如 G/B、D/F#。
- 安装包命名：每个 Android 构建产物应带有软件版本号，避免不同版本安装包使用相同文件名导致混淆。

V1.2 完成标准：

- 用户能收藏当前和弦，并在收藏区域看到该和弦。
- 用户再次打开应用后，收藏内容仍存在。
- 用户查询不同和弦后，最近查询区域能按最近优先显示。
- 用户能点击收藏或最近查询中的和弦按钮重新打开结果页。
- 新增 V1.2 和弦均可查询、显示组成音、显示按法和播放试听。
- V1.2 安装包文件名中包含版本号，例如 `guitar-chord-dictionary-v1.2-debug.apk`。

### 10.4 V1.3 导出与界面升级版

V1.3 继续只面向 Android，不开发 HarmonyOS、iOS、网页端或桌面端。本版本在 V1.2 基础上增加指法图片批量导出能力，并对移动端界面做完整视觉升级。

V1.3 应实现以下需求：

- 批量导出当前和弦指法：用户应能将当前查询和弦下的全部可用按法一次性导出为图片。
- 批量导出收藏和弦指法：用户应能将收藏和弦下的全部可用按法一次性导出为图片。
- 图片格式：系统应至少支持 JPG，并可扩展支持 PNG 等常见图片格式。
- 自定义文件名：用户应能输入导出文件名前缀；系统应在前缀后追加和弦名、序号和按法名称，避免批量导出文件互相覆盖。
- 自定义导出路径：用户应能通过 Android 文件夹选择器指定导出路径。
- 导出反馈：系统应在导出完成后显示成功数量、失败数量和首个文件名。
- 前端升级：界面应采用简洁轻快的移动端视觉风格，包括白色背景、黑色重点标题、浅灰功能块、圆角输入框、圆角按钮和自然过渡动画。
- 动画反馈：查询结果更新、指板图切换等关键交互应具备轻量动画反馈。

V1.3 完成标准：

- 用户能选择导出路径、设置文件名前缀和选择 JPG/PNG 格式。
- 用户能把当前和弦的多个按法批量导出为图片。
- 用户能把收藏和弦的多个按法批量导出为图片。
- 导出的图片应包含和弦名称、按法名称、组成音、音程结构、指板图和指法说明。
- V1.3 安装包文件名中包含版本号，例如 `guitar-chord-dictionary-v1.3-debug.apk`。

### 10.5 V1.4 学习闭环产品化升级版

V1.4 以 `docs/任务书.docx` 中的《吉他和弦学习应用下一阶段产品化升级任务书》为唯一新增产品依据，必须按以下顺序建立完整学习闭环：

1. 练习数据可信化：新增逐次结果，成功与失败分别持久化，旧记录不得伪造成功率。
2. 每组和弦切换统计与熟练度：方向分离，最近 20 次、最少 5 次，计算成功率、稳定 BPM、连续次数、时效与 0–100 分数。
3. 首次启动引导与学习资料：建立可跳过、可重设的本地学习档案。
4. 动态今日练习首页：使用真实资料和历史确定性生成任务，支持直接开始、调整与直接继续。
5. 练习设置优化：统一选材、速度、时长、切换方式、预设与自然语言摘要。
6. 练习难度建议：最少 10 次结果后按明确阈值调整 BPM，不依赖 AI。
7. 让新手和专业模式真正生效：页面内容、指法范围、练习默认值和高级设置应有实际差异。
8. 完整数据备份与恢复：ZIP 分区、清单校验、预览、冲突策略、事务回滚、幂等恢复且排除 API Key。
9. 基础成长看板：展示七日趋势、成功率、连续天数、方向性强弱项和稳定速度。
10. 大字体、自适应、文案和导航修正：200% 字体、横屏、TalkBack 语义及上下文入口可用。
11. 测试、构建和文档收尾：执行离线核心、Lint、单元测试、Debug、instrumentation、连接设备及 Release 门禁，真实报告失败、跳过和环境限制。

V1.4 完成标准是 AC-26 至 AC-43 均有对应实现或验证证据，并且核心学习闭环在无网络、无 AI 配置时可用。物理设备性能、硬件音频延迟和 AI 在线服务不因模拟器或离线测试而被推定通过。

### 10.6 V1.5 本地曲谱练习系统

V1.5 在 V1.4 可信学习闭环上增加离线“曲谱练习”，产品定义为：将用户已有的和弦谱转换为可移调、可分段、可循环、可固定指法和可统计的本地练习项目。它不是在线歌曲库、音乐播放器、自动扒谱或制谱/DAW 软件。

V1.5 应实现以下需求：

- 先修复 V1.4 同一播放步骤重复计数、attempt 与完成/重置/放弃竞态，以及“继续上次练习”配置不完整问题。
- 建立独立 `SongProject`、`SongSection`、`SongRow`、`SongChordEvent`、`SongPracticeRun` 与 `UserReportedDifficulty` 模型，不将歌词、段落和原文硬塞入 `ChordProgression`。
- 使用版本化、原子写入、有 `.bak` 回退和容量限制的独立曲谱项目、练习记录和困难标记 Store；稳定 ID 与重复 ID 校验必须覆盖保存、导入和恢复。
- 解析器支持行内和弦、和弦行+歌词行、纯和弦小节，识别中文/英文/自定义段落名，并复用本地和弦核心验证别名、slash chord 和 Unicode 升降号。
- 原始文本始终完整保留；低置信度、未知 token 和可能误判内容进入预览警告，允许逐行标记为和弦、歌词、段落标题或普通文本后重新解析。
- 明确区分 `UNTYPED`、`SIMPLE_MEASURES` 和 `EXPLICIT_BEATS`；无可靠拍数时不得宣称精确自动滚动、高亮或完整同步。
- 曲谱库、导入、预览、详情、编辑和练习页面进入现有“练习”体系，不增加第六个底部导航；删除、覆盖和离开未保存内容必须确认。
- 复用现有移调、变调夹、指法、`ProgressionTransport` 和绝对单调时钟；区分实际音高、手型调与 capo，支持 slash bass、升降号偏好和固定指法持久化。
- `GUIDED_TRANSITION` 对真实方向、真实播放步骤逐次写入 `TransitionAttempt`，保留 song/section 来源；同一 step token 最多一次。
- `PERFORMANCE` 只记录真实时长、完成状态、BPM 和曲谱配置；困难切换必须由用户主动勾选并写入独立模型，不能生成成功率或自动失败。
- `LearningGoal.SONG_ACCOMPANIMENT` 必须真实改变首页/今日计划；继续练习需恢复曲谱、段落、模式、BPM、移调、capo、固定指法、循环和显示设置。
- 曲谱成长看板只显示可证实的时长、次数、BPM、完成和用户困难数据，不生成麦克风正确率、连续演奏成功率或未确认切换成功。
- 完整备份增加 `song-projects.json`、`song-practice-runs.json` 和 `song-difficulties.json`，更新 manifest/checksum/预览/schema；重复恢复幂等，项目冲突创建“恢复副本”，取消或失败完整回滚，API Key 继续排除。
- 新手/专业差异统一通过 `ExperienceCapabilities` 生效；支持 200% 字体、TalkBack、深浅色、减少动画、横屏和 600dp 自适应布局。
- 版本更新为 `versionCode 6`、`versionName 1.5`，构建 Debug、AndroidTest 与 Release APK，并按机器生成报告记录测试、Lint、设备限制、大小和 SHA-256。

V1.5 明确不实现在线歌曲搜索/曲库、歌词下载、原唱播放、人声分离、自动扒谱、音视频整曲识别、社区/商城、五线谱、完整 Guitar Pro、MIDI/DAW、版权抓取、账号/云同步，以及由 AI 决定正式和弦、节拍、指法或成绩。

V1.5 完成标准以 `docs/v1.5-song-practice-implementation-report.md` 的真实验证结果为准。无连接设备时，instrumentation APK 构建成功不等于 Compose、TalkBack、200% 字体或真机性能运行通过；必须明确保留为未验证项。

### 10.7 后续版本

后续版本可从第 9 章“后续扩展方向”中继续选择功能进入开发范围。除非后续需求另行确认，以下能力不属于 V1.5 的必做范围：
